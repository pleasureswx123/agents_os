# 智能体工厂平台产品需求文档

## 1. 文档信息

- 产品名称：智能体工厂平台
- 文档类型：产品需求文档
- 当前版本：v0.1
- 创建日期：2026-06-10
- 首个业务模板：小说/故事生成视频素材包
- 目标阶段：MVP

## 2. 产品背景

当前很多 AI 应用会把“输入文本 -> 自动生成完整视频”作为目标，但完整视频生成和合成涉及节奏、转场、局部返工、软件兼容、素材管理、机器性能和审美判断，早期直接做自动成片容易失控。

本产品选择切开这个问题：平台不负责最终视频合成，而是负责把小说、故事或文章转化为可用于视频制作的结构化素材包。最终合成交给剪映、Premiere Pro、DaVinci Resolve、万兴喵影等成熟视频编辑软件。

但本产品的本质也不是一个固定的小说素材生成工具，而是一个智能体工厂平台。平台拥有者可以通过对话式调试、配置、版本管理和工作流编排，逐步打磨多个专业智能体，并将它们组成完整业务流程，最终发布成小白用户可直接使用的业务应用。

## 3. 产品定位

智能体工厂平台是一个面向 AI 开发者或业务设计者的智能体创建、调试、编排和发布平台。

第一阶段服务对象是平台拥有者本人，即懂 AI 的开发人员。该用户需要利用平台创建和打磨多个原子智能体，并将它们组合成可复用业务流程。

第二阶段服务对象是小白用户。小白用户不参与智能体配置，只使用平台拥有者发布好的业务应用，完成输入内容、运行流程、下载素材包等动作。

一句话定位：

> 一个以小说视频素材生产为首个业务模板的通用智能体工厂，用于创建、调试、版本化、编排和发布多智能体业务流程。

## 4. 产品目标

### 4.1 MVP 目标

MVP 需要完成一条从智能体创建到业务应用发布的最小闭环：

```text
基于模板创建项目
-> 创建/修改/删除/新增原子智能体
-> 配置智能体
-> 通过聊天调试智能体
-> 保存满意版本
-> 沉淀测试用例
-> 编排线性工作流
-> 运行工作流
-> 查看和编辑中间结果
-> 重跑失败节点
-> 导出结构化结果包
```

### 4.2 首个业务目标

首个模板为“小说/故事生成视频素材包”。该模板用于验证平台能力，并为后续发布给小白用户的业务应用打基础。

第一版不要求真实生成完整音频和视频文件，但必须能够产出：

- 小说分析结果。
- 角色画像。
- 场景拆解。
- 分镜脚本。
- 音频、图片、视频生成任务规划。
- 素材包目录规划。
- 字幕、剪辑表、manifest、README 等结构化文件。

### 4.3 非目标

MVP 不解决以下问题：

- 不做最终视频合成。
- 不做复杂可视化 DAG 编辑器。
- 不做多人协作和权限审批。
- 不做插件市场。
- 不做在线支付。
- 不做模型微调平台。
- 不做复杂自动评测系统。
- 不让小白用户配置 prompt、model ID、API key、tools 或 workflow。

## 5. 用户角色

### 5.1 平台拥有者

平台拥有者是第一阶段核心用户，通常是懂 AI 的开发者或业务设计者。

核心诉求：

- 快速创建不同职责的智能体。
- 方便配置 prompt、模型、API、tools、skills、输入输出格式。
- 通过聊天快速测试智能体效果。
- 对不满意输出进行反向调优。
- 保存满意版本并可回滚。
- 使用测试用例对比不同版本效果。
- 将多个智能体串成业务流程。
- 查看每一步中间结果，定位问题节点。
- 将成熟流程发布成小白用户可用的应用。

### 5.2 小白用户

小白用户是第二阶段业务应用使用者。

核心诉求：

- 不理解智能体配置也能使用业务能力。
- 只需要输入小说、故事或文章。
- 只需要选择少量业务参数。
- 能看到运行进度。
- 能下载结果素材包。
- 能把素材包导入自己熟悉的视频编辑软件。

## 6. 核心概念

### 6.1 Project

Project 是一次业务流程打磨的工作空间。

一个 Project 可以从系统模板创建，也可以从自定义模板创建。Project 内包含一组智能体、工作流、测试用例、运行记录和产物。

### 6.2 Agent

Agent 是一个可配置的原子智能体，负责完成某个明确职责，例如小说分析、角色画像、场景拆解或分镜脚本。

Agent 应具备：

- 基础信息。
- 模型配置。
- prompt 配置。
- 输入输出 schema。
- tools 和 skills 配置。
- 聊天测试记录。
- 多个版本。

### 6.3 Agent Version

Agent Version 是某个 Agent 在某一时刻的稳定配置快照。

保存版本时应记录：

- prompt。
- 模型供应商。
- base URL。
- model ID。
- runtime 参数。
- 输入 schema。
- 输出 schema。
- tools 和 skills 配置。
- 版本说明。
- 创建时间。

### 6.4 Test Case

Test Case 是用于验证智能体效果的测试样例。

测试用例可由聊天测试结果一键沉淀，也可以手动创建。

### 6.5 Workflow

Workflow 是多个智能体节点组成的业务流程。

MVP 先支持线性流程，每个节点绑定一个 Agent Version，并定义输入来源、输出位置、失败处理和是否允许人工编辑。

### 6.6 Workflow Run

Workflow Run 是一次工作流运行实例。

运行实例需要记录：

- 运行输入。
- 每个节点状态。
- 每个节点输入输出。
- 错误信息。
- 人工编辑记录。
- 产物记录。

### 6.7 Artifact

Artifact 是工作流产生的中间结果或最终结果。

Artifact 可以是结构化 JSON、Markdown、CSV、字幕文件、提示词文件、音频任务、视频任务、图片任务或未来真实媒体文件。

### 6.8 Template

Template 是项目创建起点。

模板分为：

- 系统模板：平台内置，只读。
- 项目副本：用户基于模板创建项目后得到的可编辑副本。
- 自定义模板：用户将调优后的项目保存为可复用模板。

## 7. 产品模块

### 7.1 项目与模板模块

#### 7.1.1 需求说明

平台应支持从模板创建项目。MVP 默认内置“小说/故事生成视频素材包”系统模板。

系统模板不能被直接修改。用户创建项目时，平台复制系统模板中的智能体、工作流和默认配置，生成项目副本。用户对项目副本拥有完整编辑权。

#### 7.1.2 功能需求

- 查看系统模板列表。
- 基于系统模板创建项目。
- 查看项目列表。
- 进入项目工作区。
- 修改项目名称和描述。
- 将项目保存为自定义模板。
- 查看自定义模板列表。
- 基于自定义模板创建新项目。

#### 7.1.3 验收标准

- 用户可以基于“小说/故事生成视频素材包”模板创建项目。
- 新项目中自动包含预置智能体和预置工作流。
- 修改项目中的智能体不会影响系统模板。
- 用户可以将调优后的项目保存为自定义模板。

### 7.2 Agent Studio：智能体工作台

#### 7.2.1 需求说明

Agent Studio 是平台拥有者创建、配置和调试原子智能体的主要界面。

MVP 应优先支持聊天式调试。平台拥有者可以像使用 ChatGPT 一样测试当前 Agent，并在不满意时修改配置，再次运行测试。

#### 7.2.2 功能需求

Agent 基础管理：

- 新增 Agent。
- 修改 Agent 名称和描述。
- 复制 Agent。
- 删除 Agent。
- 查看 Agent 列表。
- 按项目查看 Agent。

Agent 配置：

- 配置 system prompt。
- 配置模型供应商。
- 配置 base URL。
- 配置 API key 引用。
- 配置 model ID。
- 配置 temperature 等运行参数。
- 配置输入 schema。
- 配置输出 schema。
- 配置可用 tools。
- 配置可用 skills。

聊天式测试：

- 输入测试消息。
- 调用当前 Agent 配置生成输出。
- 展示完整对话记录。
- 展示本次调用使用的配置摘要。
- 支持将某次输入输出保存为测试用例。
- 支持将当前配置保存为版本。

版本管理：

- 创建 Agent Version。
- 查看版本列表。
- 查看版本详情。
- 将某个版本设为当前推荐版本。
- 从历史版本恢复配置。

#### 7.2.3 删除规则

如果 Agent 未被任何工作流节点引用，可以直接删除。

如果 Agent 被工作流节点引用，平台必须提示依赖关系，并提供：

```text
1. 移除相关工作流节点
2. 替换为另一个 Agent
3. 取消删除
```

#### 7.2.4 验收标准

- 用户可以创建、复制、修改和删除 Agent。
- 用户可以配置 prompt、模型和输入输出 schema。
- 用户可以通过聊天测试当前 Agent。
- 用户可以将满意配置保存为版本。
- 被工作流引用的 Agent 不会被静默删除。

### 7.3 Evaluation Lab：评测与版本对比

#### 7.3.1 需求说明

Evaluation Lab 用于辅助平台拥有者判断智能体是否越调越好。

MVP 不做复杂自动评测，先支持人工评价和版本对比。

#### 7.3.2 功能需求

- 从聊天记录创建测试用例。
- 手动创建测试用例。
- 编辑测试输入。
- 编辑期望输出说明。
- 运行单个测试用例。
- 对输出标记满意、一般、不满意。
- 添加人工备注。
- 对比同一测试输入在多个 Agent Version 下的输出。

#### 7.3.3 验收标准

- 用户可以把一次满意或不满意的聊天结果保存为测试用例。
- 用户可以用同一个测试输入运行多个版本。
- 用户可以人工标记每个输出质量。
- 用户可以查看不同版本输出差异。

### 7.4 Workflow Builder：工作流编排器

#### 7.4.1 需求说明

Workflow Builder 用于将多个 Agent 组成完整业务流程。

MVP 先支持线性工作流，不做复杂 DAG。每个节点绑定一个 Agent Version，并从上游节点或项目输入中读取数据。

#### 7.4.2 功能需求

Workflow 管理：

- 创建 Workflow。
- 编辑 Workflow 名称和描述。
- 查看 Workflow 节点列表。
- 删除 Workflow。
- 复制 Workflow。

节点管理：

- 新增节点。
- 删除节点。
- 禁用节点。
- 调整节点顺序。
- 为节点选择 Agent Version。
- 配置节点输入来源。
- 配置节点输出位置。
- 配置失败处理方式。
- 配置节点输出是否允许人工编辑。

工作流运行：

- 输入工作流初始内容。
- 启动工作流运行。
- 按节点顺序执行。
- 展示节点状态：等待中、运行中、成功、失败、已跳过。
- 查看每个节点输入。
- 查看每个节点输出。
- 手动编辑节点输出。
- 从失败节点重跑。
- 从指定节点继续运行。

#### 7.4.3 验收标准

- 用户可以将多个 Agent Version 组成线性流程。
- 用户可以运行完整流程。
- 用户可以查看每一步输入输出。
- 用户可以编辑中间结果后继续执行。
- 节点失败时，用户可以看到错误并重跑该节点。

### 7.5 Artifact Manager：产物与素材包管理

#### 7.5.1 需求说明

Artifact Manager 负责保存、组织和导出工作流产物。

MVP 的重点是结构化文本资产和生成规划，不要求完整真实媒体生成。

#### 7.5.2 功能需求

- 保存每个节点的结构化输出。
- 保存最终导出结果。
- 生成 manifest.json。
- 生成 README.md。
- 生成剪辑计划文件。
- 生成字幕文件草案。
- 生成音频任务清单。
- 生成视频任务清单。
- 生成图片提示词清单。
- 支持将结果打包导出为文件夹或压缩包。

#### 7.5.3 推荐导出目录

```text
project-name/
  01_script/
  02_voiceover/
  03_dialogue/
  04_video_clips/
  05_images/
  06_sfx/
  07_subtitles/
  edit_plan.csv
  manifest.json
  README.md
```

#### 7.5.4 验收标准

- 用户可以导出一次工作流运行的结果包。
- 结果包中包含 manifest 和 README。
- 结果包中的文件能追溯到对应 workflow run、节点和 Agent Version。
- 即使尚未接入真实媒体生成，结果包也应包含清晰的生成任务和素材规划。

### 7.6 Published App：小白应用端

#### 7.6.1 需求说明

Published App 是成熟工作流对小白用户开放后的简化入口。

MVP 需要实现最小发布能力，但发布能力必须从第一版开始绑定 Workflow 发布快照，而不是直接绑定可编辑 Workflow 草稿。第一版不需要完整运营后台。

#### 7.6.2 功能需求

- 将某个 Workflow 标记为可发布。
- 配置应用名称、说明和输入字段。
- 配置小白用户可见参数，例如风格、画面比例、输出精细度。
- 提供简化运行页面。
- 支持粘贴或上传文本。
- 支持启动流程。
- 展示运行进度。
- 展示完成状态。
- 下载结果包。

#### 7.6.3 验收标准

- 小白用户不需要看到 Agent 配置。
- 小白用户可以输入文本并启动已发布流程。
- 小白用户可以查看进度并下载素材包。

## 8. 首个内置模板需求

### 8.1 模板名称

小说/故事生成视频素材包。

### 8.2 预置智能体

#### 8.2.1 小说分析智能体

职责：

- 理解整篇小说、故事或文章。
- 输出故事概要、章节结构、主要角色、风格、情绪基调和叙事重点。

#### 8.2.2 角色画像智能体

职责：

- 基于小说分析结果提取角色。
- 输出角色性格、外貌、关系、动机、声音建议和画面表现建议。

#### 8.2.3 场景拆解智能体

职责：

- 将故事拆分为可制作素材的场景。
- 输出每个场景的地点、人物、事件、情绪、冲突和连续性说明。

#### 8.2.4 分镜脚本智能体

职责：

- 将场景转化为镜头。
- 输出镜头描述、旁白、字幕文本、画面提示词和预计时长。

#### 8.2.5 素材生成规划智能体

职责：

- 根据分镜脚本生成素材需求。
- 输出音频任务、图片任务、视频任务、音效任务和生成提示词。

#### 8.2.6 素材包整理智能体

职责：

- 将前序结果整理成可导出素材包。
- 输出 manifest、README、剪辑计划、字幕文件和文件命名规则。

### 8.3 默认工作流

```text
输入小说/故事
-> 小说分析智能体
-> 角色画像智能体
-> 场景拆解智能体
-> 分镜脚本智能体
-> 素材生成规划智能体
-> 素材包整理智能体
-> 导出素材包
```

### 8.4 模板编辑要求

基于模板创建项目后，用户必须可以：

- 修改任意预置智能体。
- 删除任意预置智能体。
- 新增智能体。
- 复制智能体。
- 替换工作流节点中的智能体。
- 调整节点顺序。
- 禁用节点。
- 将调整后的项目保存为自定义模板。

```text
左侧：Workflow 列表
```

需要展示：

- 本次运行状态。

- 进度状态。
- 结果下载入口。

- workflow_run_id
- workflow_node_run_id
- type
- path
- metadata
- created_at

## 11. 权限与配置边界

MVP 按单组织单管理员设计，但从第一版开始使用 JWT + Refresh Token 建立稳定鉴权边界。不做复杂角色权限、OAuth、SSO 和套餐权限。

需要注意：

- API key 不应明文展示。
- API key 应通过引用方式绑定到 Agent Version。
- 导出的素材包不应包含 API key。
- 小白应用端不应暴露模型供应商、prompt 或工作流内部配置。

## 12. 非功能需求

### 12.1 可调试性

平台必须保留每次运行的输入、输出、错误和使用的 Agent Version，方便定位问题。

### 12.2 可追溯性

最终导出素材应能追溯到：

- 项目。
- 工作流。
- 工作流运行。
- 节点。
- Agent Version。
- 原文片段。

### 12.3 可恢复性

用户应能从历史 Agent Version 恢复配置。Workflow 节点失败后，应能从失败节点重跑。

### 12.4 可扩展性

虽然 MVP 先做 LLM 文本智能体，但 Tool / Provider 调用结构应从第一版开始建立，以便后续在同一架构上接入：

- 音频生成。
- 图片生成。
- 视频生成。
- 文件处理。
- 字幕生成。
- 外部素材库。

### 12.5 易用性

平台拥有者侧可以暴露较多专业配置，但小白应用端必须极简，避免让最终用户理解智能体、prompt、model、tool 等概念。

## 13. MVP 迭代拆分建议

### 13.1 第一迭代：智能体工作台闭环

目标：

- 支持项目创建。
- 支持 Agent 创建和配置。
- 支持聊天式测试。
- 支持保存 Agent Version。
- 支持从聊天结果创建测试用例。

### 13.2 第二迭代：工作流运行闭环

目标：

- 支持线性 Workflow。
- 支持节点绑定 Agent Version。
- 支持运行工作流。
- 支持查看中间输入输出。
- 支持失败节点重跑。

### 13.3 第三迭代：小说素材模板闭环

目标：

- 内置小说视频素材生产模板。
- 预置六类 Agent。
- 预置默认工作流。
- 支持导出结构化结果包。

### 13.4 第四迭代：小白应用发布闭环

目标：

- 支持将 Workflow 发布为简化应用。
- 支持小白输入文本并运行。
- 支持查看进度和下载结果包。

## 14. 风险与应对

### 14.1 过早平台化风险

风险：一开始追求通用平台，导致抽象复杂、没有可验证业务价值。

应对：底层保持通用，首个体验强绑定小说视频素材生产模板。

### 14.2 过早媒体生成风险

风险：音频、图片、视频生成供应商差异大，异步任务、失败重试和成本控制会拖慢 MVP。

应对：MVP 即定义 Tool / Provider 调用结构，先产出结构化生成任务和提示词，后续新增音频、图片、视频 Provider 实现，不改变上层 Workflow 调用模型。

### 14.3 调参不可控风险

风险：用户不断修改 prompt，却不知道哪版更好。

应对：引入 Agent Version、Test Case、人工评分和版本对比。

### 14.4 工作流断裂风险

风险：上游输出格式变化导致下游 Agent 无法处理。

应对：每个 Agent 必须定义输入输出 schema，Workflow 运行时保存中间结果，并允许人工编辑后继续。

### 14.5 小白端复杂度失控风险

风险：把工厂侧配置暴露给小白用户，导致使用门槛过高。

应对：小白端只显示输入、少量业务参数、运行进度和下载入口。

## 15. 验收总标准

MVP 可以认为完成，当满足以下标准：

- 可以基于“小说/故事生成视频素材包”模板创建项目。
- 项目中自动生成预置 Agent 和默认 Workflow。
- 平台拥有者可以修改、删除、新增和复制 Agent。
- 平台拥有者可以通过聊天测试 Agent。
- 平台拥有者可以保存 Agent Version。
- 平台拥有者可以把聊天结果保存为测试用例。
- 平台拥有者可以创建线性 Workflow 并绑定 Agent Version。
- 平台可以执行一次完整 Workflow Run。
- 平台可以展示每个节点的输入、输出、状态和错误。
- 平台支持编辑中间输出并继续运行。
- 平台支持失败节点重跑。
- 平台可以导出结构化素材规划包。
- 平台可以发布一个简化的小白应用入口。
- 小白用户可以输入故事并下载生成结果包。

## 16. 后续扩展方向

MVP 之后可以逐步扩展：

- 接入真实音频生成工具。
- 接入真实图片生成工具。
- 接入真实视频生成工具。
- 多队列 BullMQ Worker 扩展。
- 多对象存储后端和跨区域存储策略。
- 支持更复杂的 DAG 工作流。
- 支持自动评测和批量回归测试。
- 支持模板市场。
- 支持多用户协作。
- 支持运行成本统计。
- 支持素材库和复用管理。
- 支持导出剪映、PR 或达芬奇更友好的工程辅助格式。
