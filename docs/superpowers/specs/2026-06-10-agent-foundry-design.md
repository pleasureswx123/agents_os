# 智能体工厂产品设计草案

## 1. 产品定位

本产品是一个面向懂 AI 的开发者或业务设计者的智能体工厂平台。

它不是一个单一的“小说转视频”工具，也不是第一版就面向小白用户开放的通用无代码智能体平台。它的目标是帮助平台拥有者创建、配置、测试、调优、版本化和编排多个专业智能体，然后把成熟的业务流程发布成一个小白用户可直接使用的业务应用。

首个业务场景是：

> 小白用户输入一整篇小说、故事或文章。已发布的业务流程产出多个音频和视频相关素材，并导出一个结构化素材包。最终视频合成被有意排除在平台之外，交给剪映、Premiere Pro、DaVinci Resolve、万兴喵影等成熟桌面视频编辑软件完成。

因此，平台需要支持两层能力：

- 智能体工厂：由 AI 开发者使用，用于创建、调试和打磨智能体。
- 已发布智能体应用：由小白用户使用，用于以极少配置运行成熟业务流程。

## 2. 核心产品目标

核心目标是：

> 构建一个通用的智能体和工作流底座，同时以“小说/故事生成视频素材包”作为第一个具体模板和验证场景。

第一版应遵循这个原则：

> 底层是通用的，第一体验是具体的。

这意味着数据模型和运行时应围绕 Agent、Agent Version、Tool、Skill、Workflow、Workflow Run、Artifact 等通用概念设计。但默认模板、初始界面路径和第一条验证流程应聚焦在小说视频素材生产场景。

## 3. 目标用户

### 3.1 第一阶段用户

第一阶段用户是平台拥有者：懂 AI 的开发者或业务设计者。

这个用户需要：

- 创建专业化的原子智能体。
- 配置 prompt、模型供应商、model ID、API key、tools、skills 和输出 schema。
- 通过聊天测试智能体。
- 根据不满意的输出调整智能体行为。
- 保存稳定的智能体版本。
- 将优秀的输入/输出样例沉淀为测试用例。
- 将多个智能体编排成业务工作流。
- 调试工作流中的每一步，并重跑失败节点。
- 将成熟工作流发布成面向小白用户的简化应用。

### 3.2 第二阶段用户

第二阶段用户是小白内容创作者或运营人员。

这个用户不应接触底层智能体配置。他们只需要：

- 选择或打开一个已发布的业务应用。
- 粘贴或上传故事、文章或小说。
- 选择少量业务参数，例如风格、时长、画面比例或输出精细度。
- 启动流程。
- 查看进度。
- 下载生成的素材包。
- 将导出的素材导入自己的视频编辑软件中完成最终合成。

## 4. 产品结构

产品有两条主线。

### 4.1 智能体工厂线

这条线由 AI 开发者使用。

核心流程是：

```text
创建原子智能体
-> 配置智能体
-> 通过聊天测试
-> 调整配置
-> 保存智能体版本
-> 将优秀样例转为测试用例
-> 将多个智能体编排成工作流
-> 运行工作流
-> 查看中间输出
-> 重跑或修正失败步骤
-> 发布为小白用户可使用的应用
```

### 4.2 小白应用线

这条线由工作流发布后的小白用户使用。

核心流程是：

```text
打开已发布应用
-> 输入小说或故事
-> 设置少量业务参数
-> 运行
-> 查看进度
-> 下载结构化素材包
-> 在外部视频编辑软件中合成最终视频
```

## 5. 核心系统

### 5.1 Agent Studio：智能体工作台

Agent Studio 是创建和调优原子智能体的工作区。

一个原子智能体应支持这些配置项：

- 名称。
- 描述。
- 系统提示词。
- 模型供应商。
- Base URL。
- API key 引用。
- Model ID。
- temperature 等运行参数。
- 输入 schema。
- 输出 schema。
- 可用 tools。
- 可用 skills。

第一版应优先支持聊天式调试：

```text
修改 prompt
-> 运行一次聊天测试
-> 查看输出
-> 调整配置
-> 保存满意版本
```

推荐界面模式是：

```text
左侧：智能体列表
中间：聊天测试区
右侧：配置、版本和测试用例
```

### 5.2 Evaluation Lab：评测与版本对比

Evaluation Lab 用于回答：

> 这个智能体在最近一次调整后是否真的变好了？

第一版不需要复杂的自动评分系统，应先支持简单的人工评价。

每个测试用例可以保存：

- 测试输入。
- 期望输出说明。
- 实际输出。
- 人工评分：满意、一般、不满意。
- 备注。
- 关联的智能体版本。

平台应支持使用同一个输入对比多个版本：

```text
同一个测试输入
-> Version 1 输出
-> Version 2 输出
-> Version 3 输出
-> 人工选择更满意的版本
```

### 5.3 Workflow Builder：工作流编排器

Workflow Builder 用于将多个原子智能体组合成一个完整业务流程。

第一版不应从复杂的拖拽式 DAG 编辑器开始。它应先支持更简单的线性工作流，同时保留足够的真实调试能力。

每个工作流节点应定义：

- 使用哪个智能体版本。
- 输入来自哪里。
- 输出保存到哪里。
- 输出是否允许在进入下一步前人工编辑。
- 失败时如何处理。
- 节点是否可禁用、替换或重跑。

工作流必须让中间输出可见、可编辑。这一点非常关键，因为业务流程质量问题通常出现在中间步骤，而不只是最终输出。

### 5.4 Artifact Manager：产物与素材管理器

Artifact Manager 用于保存和导出工作流结果。

在小说视频素材场景中，最终导出的不是完整视频，而是一个结构化素材包。

示例结构：

```text
project-name/
  01_script/
  02_voiceover/
  03_dialogue/
  04_video_clips/
  05_images/
  06_sfx/
  07_subtitles/
  edit_plan.csv
  manifest.json
  README.md
```

素材包应保留可追溯信息：

- 该素材由哪次工作流运行产生。
- 该素材由哪个节点产生。
- 该素材由哪个智能体版本产生。
- 该素材对应原文中的哪个文本片段。

## 6. 首个模板：小说视频素材生产

第一个内置模板应为“小说/故事生成视频素材包”。

当用户基于该模板创建项目时，平台应生成一个项目副本，副本中包含预置智能体和预置工作流。

初始智能体可以包括：

- 小说分析智能体。
- 角色画像智能体。
- 场景拆解智能体。
- 分镜脚本智能体。
- 素材生成规划智能体。
- 素材包整理智能体。

第一版应以 LLM 文本智能体为主，同时预留 tool 调用结构。

推荐的第一阶段工作流：

```text
1. 小说分析智能体
   输出：故事概要、章节、主要角色、风格、情绪基调。

2. 角色画像智能体
   输出：角色列表、性格、外貌、声音建议、人物关系。

3. 场景拆解智能体
   输出：场景列表、地点、出场人物、事件、情绪、连续性说明。

4. 分镜脚本智能体
   输出：镜头列表、旁白、画面描述、预计时长、字幕文本。

5. 素材生成规划智能体
   输出：音频任务、视频任务、图片提示词、音效需求。

6. 素材包整理智能体
   输出：导出 manifest、字幕、剪辑计划、文件命名规则、README。
```

在第一个 MVP 中，真实音频和视频生成可以后续通过 tool 接口接入。第一版至少应产出结构化生成任务、提示词、manifest 和可导出的规划文件。

## 7. 模板编辑规则

模板是起点，不是限制。

平台应支持三个层级：

### 7.1 系统模板

系统模板是平台内置的原始模板，例如：

```text
小说视频素材生产模板 v1
```

它应为只读，这样平台拥有者可以随时回到原始基线。

### 7.2 项目副本

当用户基于系统模板创建项目时，平台会把预置智能体和工作流复制到项目中。

用户编辑的是这个项目副本，而不是原始系统模板。

在项目中，用户可以：

- 修改预置智能体。
- 删除智能体。
- 复制智能体。
- 新增智能体。
- 替换工作流节点使用的智能体。
- 调整工作流节点顺序。
- 新增中间工作流节点。
- 禁用节点。
- 将项目保存为自定义模板。

### 7.3 自定义模板

项目工作流调优完成后，用户可以将其保存为自定义模板，例如：

```text
悬疑小说视频素材模板
儿童故事绘本素材模板
短剧分镜模板
```

自定义模板可以在未来项目中复用，也可以发布成面向小白用户的业务应用。

## 8. 智能体删除与依赖规则

如果某个智能体正在被工作流节点引用，不应静默删除。

平台应展示哪些工作流节点依赖该智能体，并提供选择：

```text
该智能体正在被以下节点使用：
- 场景拆解流程步骤
- 素材规划流程步骤

请选择：
1. 移除相关工作流节点。
2. 将该智能体替换为另一个智能体。
3. 取消删除。
```

这可以防止工作流被破坏，并让依赖关系保持清晰。

## 9. MVP 范围

### 9.1 必须包含

MVP 应包含：

- 基于小说视频素材生产模板创建项目。
- 创建智能体。
- 配置智能体。
- 聊天式智能体测试。
- 保存智能体版本。
- 从聊天样例创建基础测试用例。
- 对输出进行简单人工评分。
- 线性工作流编排。
- 执行工作流运行。
- 查看中间输出。
- 手动编辑中间输出。
- 重跑失败节点。
- 导出结构化结果。
- 为未来音频和视频生成预留 tool 调用结构。

### 9.2 MVP 暂不包含

MVP 暂不包含：

- 复杂可视化 DAG 编辑器。
- 多租户权限系统。
- 在线支付。
- 插件市场。
- 自动模型微调。
- 复杂自动评测。
- 完整视频合成。
- 面向小白用户的高级配置。
- 多人协作审批流程。

## 10. 关键产品边界

### 10.1 产品不负责最终视频合成

平台产出素材和结构化剪辑指导，不在第一版中替代专业视频编辑软件。

这是一个有意为之的边界。最终视频合成涉及节奏、转场、视觉审美、反复调整、本地性能和软件特定工作流。成熟视频编辑工具更适合完成这个步骤。

### 10.2 第一版不需要完整媒体生成能力

第一版应先支持 LLM 文本智能体，并为未来音频、图片和视频生成预留 tool 结构。

这样可以避免过早被媒体供应商差异、异步任务处理、成本控制、文件存储和重试逻辑拖住。

### 10.3 小白用户不配置智能体

小白用户只应操作已发布的业务应用。他们不应编辑 prompt、model ID、API key、tools 或工作流逻辑。

## 11. 已确定关键技术决策

进入实现规划前，以下关键决策已经确定：

1. MVP 采用 React 19 + TypeScript 前端、Node.js 24 LTS + NestJS 后端。
2. MVP 使用 React Flow 作为工作流画布，但第一版只开放线性流程模式。
3. MVP 使用 Socket.IO / WebSocket 作为双向实时通信基础，不使用 SSE 或轮询作为主要实时方案。
4. MVP 使用 BullMQ + Redis 执行 WorkflowRun / NodeRun，不使用同步 HTTP 长请求执行工作流。
5. MVP 使用 S3 兼容对象存储接口，开发和私有化默认 MinIO。
6. MVP 使用 JWT + Refresh Token，第一版只开放单组织单管理员能力。
7. 系统模板由 seed 初始化到数据库，运行时按 Template / TemplateVersion 管理。
8. Published App 绑定 WorkflowSnapshot 发布快照，不直接绑定可编辑 Workflow 草稿。
9. 模型供应商凭据通过 ProviderConfig 和 apiKeyRef 管理，不在 Agent 配置和导出包中保存明文 key。
10. 小白应用端可以先放在同一 Web 应用内的简化路由中，但必须与工厂侧配置隔离。

## 12. 当前建议

推荐的 MVP 方向是：

> 先构建一个面向 AI 开发者的本地或自托管 Web 应用。底层使用通用 Agent 和 Workflow 基础模型，但内置一个具体的小说视频素材生产模板。先支持聊天式智能体调优和线性工作流执行。第一版先导出结构化文本资产和生成规划，同时为后续真实音频、图片、视频生成预留 tool 接口。

这样既能用真实业务场景验证平台，又不会把底层能力过度绑定到单一流程。
